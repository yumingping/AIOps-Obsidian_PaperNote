# 多模态观测（metrics、logs、traces）

**一句话定义**：微服务系统的三类互补遥测数据——metrics（数值运行状态）、logs（半结构化文本事件）、traces（请求级调用路径与 span 延迟）。

**通俗解释（研0 版）**：给系统体检要看三类材料：metrics 像体温血压（数字指标），logs 像病历记录（一条条文字日志），traces 像就诊流程单（请求依次走过哪些科室、在哪一步耽搁）。只看一项容易误诊，三项合看才完整——麻烦在于三种材料格式完全不同，怎么拼到一起是门学问。

## 要点
- 采集成本差异巨大：metrics/logs 无需改源码（监控代理/service mesh 即可），trace 需要分布式追踪埋点（论文9 p.4）。
- 异质性：格式、时间粒度、语义都不同，对齐困难（论文12 p.2–3）。
- 融合方式谱系：简单拼接/加权（早期多模态方法）→ 特征级融合（DiagFusion）→ 图级融合 + 跨模态对比一致性（论文12 Topo-MFP）→ 转时间序列后统一处理、缺失源填 0（论文9 TORAI）。
- 日志语义的价值：SBERT 编码模板是论文12 检测与 RCA 的最大功臣（消融 F1 0.949→0.889，Hit@1 0.872→0.813，p.17、p.19）；论文9 则只用日志模板出现次数、放弃语义。
