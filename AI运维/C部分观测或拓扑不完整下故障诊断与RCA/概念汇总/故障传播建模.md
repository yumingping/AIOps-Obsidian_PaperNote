# 故障传播建模

**一句话定义**：刻画故障（异常）如何沿服务依赖在系统中扩散的建模，目标是区分「根因服务」和「被连累的下游服务」。

**通俗解释（研0 版）**：故障像感冒会传染——一个服务出问题，依赖它的服务会陆续跟着出问题。传播建模就是研究这场「传染」沿什么路径扩散，好分清谁是第一个得病的（根因），谁只是被传染的（受害者）——像流行病学调查里找零号病人。

## 要点
- 症状常出现在下游/KPI，定位需「症状→源头」反向追溯（论文12 p.10）。
- 表示方式：因果图（论文9 CausalRanker，入度为零 = 根因候选，p.8）vs 学习出的传播图（论文12 的 $A_{prop}$，明确声明**不是验证过的因果图**，只是排序表示，p.10、p.21）。
- 关键事实：调用方向 ≠ 故障传播方向（重试、队列、异步、共享资源都会干扰），所以论文12 用双向邻接定义拓扑相邻、让多模态证据决定方向（论文12 p.10）。
- 局部异常分数不足以定位根因：Local-Score 基线 Hit@1 仅 0.584/0.692（论文12 p.18–19）。
- 边级真值缺失导致传播模型难以直接验证（论文12 p.21）。
