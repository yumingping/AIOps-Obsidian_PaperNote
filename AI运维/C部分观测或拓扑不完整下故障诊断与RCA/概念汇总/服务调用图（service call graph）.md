# 服务调用图（service call graph）

**一句话定义**：以服务为节点、调用关系为有向边的图，通常由分布式 trace 构建或多模态遥测学出，是多源微服务 RCA 的传统骨架。

**通俗解释（研0 版）**：把一段段「快递轨迹」（调用链）汇总起来，就得到一张所有服务之间谁调用谁的地图——服务是站点、调用是路线。排查故障就能顺着路线往上游找源头；但这张图常常画不全，因为有些站点压根没装记录仪（没埋点的盲点服务）。

## 要点
- 传统多源 RCA 靠 trace 建图，再把 metrics/logs 挂到图上诊断（论文9 p.2、p.4）。
- 前提假设「全量 trace 覆盖」在现实中不成立：新服务来不及埋点、闭源组件不可埋点 → 图不完整（论文9 p.4）。
- trace 只能给出调用方向，故障传播方向未必与之相同（论文12 p.10）。
- 调用图可作为「硬骨架」（CIRCA 直接建因果图）、「软先验」（论文12 Topo-MFP 的 ρ_in/ρ_out 惩罚）或被彻底抛弃（论文9 TORAI）。

## 在本部分的角色
C3 两篇论文对调用图的三种态度（硬用 / 软用 / 弃用）构成核心对照。
