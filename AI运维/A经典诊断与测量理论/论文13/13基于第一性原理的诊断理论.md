## 一、preview（p.57）
### 痛点 / 已有方法为什么不行
#### 1. 经验派（experiential approach）当道
- MYCIN（MYCIN：斯坦福大学 1970 年代开发的血液感染医疗专家系统，最有名的早期 AI 诊断程序——它不模拟人体怎么工作，只背了约 600 条「症状→抗生素」经验规则、给每条打可信度分，像老医生凭经验开方）这类专家系统把人类诊断专家的经验规则、统计直觉、案例积累编码进系统，**真实系统的结构/设计知识几乎没有表示**（p.57–58）。
- **这不行！** 经验换个设备/领域就失效，也无法解释"为什么是这个部件坏了"——诊断结论没有"深知识"（deep knowledge）支撑。
#### 2. 第一性原理（diagnosis from first principles）路线有实践、没理论
- de Kleer [1976]、Genesereth（DART：Genesereth 1984 年在斯坦福建的诊断程序——把设备描述与观测写成逻辑公式，直接调用通用定理证明器从矛盾中捞出「嫌疑人」部件清单，思路对，但从未给「诊断」下过正式定义）、Davis 等都在做"从系统结构与部件行为模型推出故障"，但**全是未形式化的直觉做法**（p.58）：
    - 没有严格定义"什么叫诊断"（尤其多故障情形）；
    - 没有可证明正确性的算法；
    - 各家系统互相之间没法比较。

### 新方法（一段话）
把系统抽象成逻辑——初始用一阶逻辑（first-order logic，一阶谓词逻辑：能说「对所有 x…」「存在某个 x…」的数理逻辑，比只会真/假的命题逻辑强一档，够写出「若与门 X 正常则输出等于两输入之与」这类部件公理），后面证明任何"二值语义 + 含 ∧,∨,¬"的逻辑都行（p.86–87）。把"诊断"定义为**一个极小的部件集合**：假设这些部件异常（AB）、其余正常时，系统描述与观测恢复一致。在这一个定义之上推出全部核心结果：诊断 = [[冲突集（conflict set）]] 的 [[最小命中集（minimal hitting set）]]（定理 4.4）、计算所有诊断的剪枝 HS-tree 算法 DIAGNOSE、单故障诊断的专门刻画、测量对诊断影响的定性理论，以及诊断与默认逻辑的一一对应。

**关键 trick**：用 McCarthy 的 **AB 谓词**（**AB**normal，异常谓词；$AB(x)$ 为真表示部件 $x$ 被假设为故障，下同）把"部件正常"从事实降级为**可撤回的逻辑假设**，于是诊断变成纯逻辑的"一致性恢复"问题——**不需要任何故障模型**（fault model），只需要正确行为模型。

## 二、introduction（p.57–59）
1. 现实痛点：诊断推理文献里并存两条路线（p.57–58）——
    1. **第一性原理**（[[基于第一性原理的诊断]]）：唯一可用信息 = 系统描述（设计/结构）+ 行为观测，**没有任何**"这类症状 90% 是这个件坏了"式的启发式统计；
    2. **经验派**：编码专家的 rules of thumb（MYCIN 是代表）。
2. 诊断问题的直觉定义（p.58）：观测与"所有部件正常时应有的行为"逻辑冲突 → 求出**哪些部件假设为坏时能解释该矛盾**。
3. 诊断不唯一：同一故障系统可能有多个竞争诊断（competing diagnoses），需要靠**测量**（电路插探针、病人做化验）甄别。
4. 计算目标：求出**所有**诊断。论文把"algorithm"打引号——因为一般情形一致性不可判定（见 §三.5）。

### 本文贡献（p.59 + §8 总结, p.94）
1. 基于一致性保持（consistency-based）的**诊断定义**，首次覆盖多故障诊断。
2. 显式使用 AB 谓词表示故障与故障间关系。
3. 理论对**任意合适的逻辑**都成立（不锁死一阶逻辑）。
4. 计算所有诊断的算法 DIAGNOSE。
5. 单故障诊断的刻画与计算方法。
6. 测量对诊断影响的若干结果（第 5 节）。
7. 揭示诊断的非单调本性（非单调推理 non-monotonic reasoning：新信息能让旧结论作废的推理——经典逻辑里推出的结论永远成立，而诊断里「所有部件正常」会被一次新测量直接推翻，信息变多、结论反而变少）：与**默认逻辑**（default logic，Reiter 1980 提出的非单调推理形式化，规则形如「没有反面证据时默认 P 成立」，详见 §八.2）的一一对应（定理 6.1）。

## 三、系统、观测与诊断的形式化（p.59–66）
1. **定义 2.1：系统（p.59）**
    - **含义**：系统 = 二元组 (SD, COMPONENTS)，见 [[系统模型 SD 与 AB]]：$SD$（**S**ystem **D**escription，系统描述，一阶逻辑句子集合，下同）；$COMPONENTS$（有限部件常量集合，下同）。为最大通用性，"部件""交互部件集合"都被抽象到极致——电路、医学、数据库共用这一个模子。
2. **AB 谓词与正常行为公理（p.60–62）**
    - **含义**：SD 中有特异一元谓词 $AB(\cdot)$。每个部件类型一条正常行为公理（记号：$\supset$ 蕴涵、$\wedge$ 且、$\vee$ 或、$\neg$ 非，下同）：
    $$\text{ANDG}(X) \wedge \neg AB(X) \supset \text{out}(x) = \text{and}(\text{in1}(x), \text{in2}(x))$$
    （异或门、或门同理。）
    - **为什么需要**：它把"部件正常"变成可撤回假设——非单调性的入口。AB 借自 McCarthy 的 circumscription（限定理论：把「异常的东西尽可能少」变成推理原则——只考虑异常对象最少的那类模型才算「正常世界」，出现矛盾就撤回假设、换一个世界再试）（p.62），Reiter 预告这层看似薄弱的联系"实际上是根本性的"。
    - 例子极 liberating（p.61–62）：
        - 医学：`ADULT(X) ∧ HEART-OF(X,h) ∧ ¬AB(h) ⊃ 70 ≤ rate(h) ≤ 90`；
        - 器件：齐纳二极管正向电压小于击穿电压时电流为零；
        - 故障传播：`AB(C1) ⊃ AB(C2)`；
        - 故障模式枚举：`TYPE(X) ∧ AB(X) ⊃ FAULT1(X) ∨ … ∨ FAULTn(X)`；
        - 多种 AB 谓词刻画"坏电阻非开路即短路"。
3. **例 2.2：全加器（p.60，图1）**——全文跑龙套主角。
    - 部件 {X1, X2, A1, A2, O1}（两个异或、两个与、一个或门）+ 布尔代数公理 + 输入取值公理。
    - 观测（p.62）：输入 1,0,1，输出 1,0——**两个输出都错**，电路有故障。

![[13-Fig1_p4.png]]
*图1（p.60）：全加器。A1、A2 是与门，X1、X2 是异或门，O1 是或门——Reiter 全文用它演示诊断。*

**图解**：这是一张门级电路图，画的是一个一位全加器（full adder：把两个二进制位与低位进位相加、输出「和」与「进位」两个结果的电路）。怎么看：从左往右读——最左是三根输入线；X1 先算前两个输入的异或，输出一路向上送给 X2、一路向下弯给 A2；X2 把 X1 的结果再与第三个输入异或，输出「和」；A1、A2 各算一对输入的与，O1 把 A1、A2 的结果取或，输出「进位」。注意 A1 的两个输入是原始输入、不经过任何别的门——这个细节在下面排除嫌疑时要用。读图结论：正常时应满足「和 = in1⊕in2⊕in3、进位 = (in1∧in2)∨((in1⊕in2)∧in3)」。代入论文的观测输入 1,0,1：和应为 0、进位应为 1；实测 1 和 0——两个输出全错，这就是 §三.3「输入 1,0,1，输出 1,0——两个输出都错」的出处，也是全文诊断推导的起点。

    - **跟读一遍：三个诊断怎么一步步长出来**。第 1 步找冲突：「和」错了，能决定「和」的只有 X2（直接算它）与 X1（喂给 X2 中间值），得冲突集 {X1, X2}——这俩不可能同时正常；「进位」错了，进位由 O1 输出，O1 的输入来自 A1、A2，而 A1 算的是 in1∧in2=1∧0=0、输入是原始输入，怪不到它头上，嫌疑只剩 X1（A2 的输入来源）、A2、O1，得第二个冲突集 {X1, A2, O1}。第 2 步求极小命中集：{X1}、{X2,A2}、{X2,O1} 恰好各命中两条冲突。第 3 步抽验最简单的 {X1}：假设 X1 坏且卡死输出 0，则 X2=0⊕1=1（实测「和」✓）、A2=0∧1=0、A1=0、O1=0∨0=0（实测「进位」✓）——一个坏门解释全部症状，这就是 §六「单故障诊断天然更可信」的活例子。

4. **定义 2.4：诊断 + 简约原则（p.63）**
    - **含义**：$\{\neg AB(C_1),\dots,\neg AB(C_n)\}$ 表示"所有部件正常"假设集合。系统有故障即
    $$SD \cup OBS \cup \{\neg AB(C_1), \dots, \neg AB(C_n)\} \quad (2.1)$$
    不一致（记号：$OBS$（**OBS**ervations，观测句子集，如电路的输入输出取值断言）、$\cup$ 并集、$C_1,\dots,C_n$ 与 $c$ 均指 COMPONENTS 中的部件，下同）。**诊断** = 极小集 $\Delta$（希腊字母 Delta，此处指被假设为故障的部件集合，下同）$\subseteq \text{COMPONENTS}$，使得
    $$SD \cup OBS \cup \{AB(c) \mid c \in \Delta\} \cup \{\neg AB(c) \mid c \in \text{COMPONENTS} - \Delta\}$$
    一致。
    - **为什么需要**：全撤回（全部件坏）总能恢复一致，但没有信息量。所以有**简约原则**（The Principle of Parsimony, p.63）：*A diagnosis is a conjecture that some minimal set of components are faulty.* 这是 [[候选诊断（candidate discrimination）]] 中"minimal"的法律来源。
    - 全加器答案（p.63）：三个诊断 {X1}、{X2, O1}、{X2, A2}。
5. **可判定性（p.63–64）**
    - 一般一阶公式的一致性无判定过程（可判定性 decidable：是否存在一个算法，对任意输入都能在有限步内明确回答「是/否」；一阶逻辑的一致性问题已被证明不存在这样的算法，属不可判定）→ 一般诊断不可计算。**但别慌**：开关电路只需判定布尔方程组有解（可判定），线性电路只需判定线性方程组有解，至少一种医学诊断模型也可计算（§7）。
    - 态度务实：每个应用先确立可判定性；不可判定就上启发式。刻画"哪些系统类的诊断问题可判定"被留作开放问题。
6. **命题 3.3 / 3.4（p.64–66）**
    - 命题 3.3：若 Δ 是诊断，则对每个 $c_i \in \Delta$，正常部件假设能**逻辑推出** AB(ci)——坏部件被好部件"逻辑决定"。
    - 命题 3.4（更简单的等价刻画）：Δ 是诊断 ⟺（当且仅当，下同）Δ 是使 $SD \cup OBS \cup \{\neg AB(c) \mid c \in \text{COMPONENTS} - \Delta\}$ 一致的极小集（AB(Δ) 那部分不必显式写）。**这是后面一切算法的跳板**。

## 四、冲突集与最小命中集：诊断的第二种刻画（p.67–68）
1. **定义 4.1：冲突集（p.67）**
    - **含义**：$\{c_1,\dots,c_k\} \subseteq \text{COMPONENTS}$ 是冲突集，当且仅当
    $$SD \cup OBS \cup \{\neg AB(c_1), \dots, \neg AB(c_k)\}$$
    不一致——"这堆部件**不可能全都正常**"。极小冲突集 = 没有真子集也是冲突集。
    - **为什么需要**：概念来自 de Kleer [1976]，被 Reiter 吸收进公理体系。它把"哪里矛盾"压缩成一小撮部件名单，是诊断计算的核心中间产物。
2. **定义 4.3：命中集（p.67）**：对集合族 $\mathcal{C}$（一族集合，下文取为冲突集族，下同），H（**H**itting set，命中集候选，下同）与族中每个 S（族中的一个集合，此处即一个冲突集）相交（$H \cap S \neq \emptyset$；$\cap$ 交集、$\emptyset$ 空集，下同）即为命中集；极小 = 无真子集也是命中集。
    > 类比（修车）：发动机「抖动」「油耗高」两个症状，师傅各圈出一串「至少有一个坏了」的嫌疑件（冲突集）；最终开的更换清单必须每个圈子里都点到一个件（命中），还要少换、少到不能再删（极小）——这份清单就是诊断，定理 4.4 说的就是这件事。
3. **定理 4.4（核心定理, p.67）**：
$$\Delta \subseteq \text{COMPONENTS 是诊断} \iff \Delta \text{ 是全部冲突集的极小命中集}$$
    - **直觉**：每个冲突集里至少得有一个真凶（否则那个冲突集的成员可以全正常，矛盾复活）；反之恰好命中每个冲突集的极小集合就能恢复一致。**诊断问题由此变成组合数学**。
    > 人话：每条冲突集线索都在喊"这堆部件里至少有一个坏了"；诊断就是一份极小的嫌疑名单，保证每条线索里都至少点到一个名字。
    - 因为冲突集的超集自动也是冲突集 → **推论 4.5**：对**极小**冲突集族求极小命中集即可。
4. **暴力法为什么不行（p.67）**：按命题 3.4 系统生成-测试所有子集（按基数从小到大），部件一多就爆炸 → 需要基于冲突集的聪明算法。
5. **全加器演示（p.68）**：两个极小冲突集 {X1, X2} 与 {X1, A2, O1}；极小命中集 = {X1}、{X2, A2}、{X2, O1}，正是三个诊断。
    - Reiter 特意注明：de Kleer & Williams（论文14）**独立**提出了与之对应的诊断刻画，"但他们的结果源于可靠的直觉，基于未形式化的方法；我们的结果从初始形式定义推出"（p.69）——同期刊上的理论 vs 引擎之争，语气相当克制。

## 五、计算所有诊断：HS-tree 与 DIAGNOSE 算法（p.69–81）
1. **HS-tree（定义 4.6, p.69）**
    - **含义**：边标号为部件、节点标号为集合的树：根标一个 F 中的集合（F = 冲突集全体）；节点 n 的根到 n 路径边标号集合记 H(n)；节点标号取一个与 H(n) 不相交的 F 中集合 S，每个 $\sigma \notin S$（$\sigma$：一个部件名，用作边标号，下同）长一条标 σ 的边；找不到不相交集合则标 √。
    - 两条基本性质（p.69）：√ 节点的 H(n) 是命中集；**每个极小命中集都是某个 √ 节点的 H(n)**（不保证枚举所有命中集，但对极小的够了）。
    - **为什么需要树**：F 不显式给出——每"访问"一次 F = 调一次定理证明器求冲突集，**极贵**。树的设计目标就是少访问。
    > 人话（医生问诊类比）：把「猜嫌疑名单」组织成一棵搜索树——树上每个节点只做一次昂贵化验（调一次定理证明器要一个冲突集），化验单上每报一个名字就岔出一条分支；同样的化验结果能外推的病人不再重做（标签复用），一眼看出不可能更小的名单直接关门（剪枝）。
2. **例 4.7（p.69，图2）**：F = {{2,4,5},{1,2,3},{1,3,5},{2,4,6},{2,4},{2,3,5},{1,6}} 的完整 HS-tree。

![[13-Fig2_p14.png]]
*图2（p.70）：例 4.7 的 HS-tree（原页横排，此处已转正），圈号节点是复用标签的源头。*

**图解**：这是例 4.7 的完整 HS-tree，画的不是电路，而是对一个抽象冲突集族 F={{2,4,5},{1,2,3},{1,3,5},{2,4,6},{2,4},{2,3,5},{1,6}} 的嫌疑枚举过程（部件用编号 1–6 代替）。怎么看：从顶端 n0 读起——节点里的花括号是节点拿到的冲突集标签，n0 标 {2,4,5}；从标签的每个成员各长一条边（边上写部件号 2、4、5），沿一条边走一步等于「把该部件记入嫌疑名单」；子节点再要一个与名单不相交的新冲突集当标签（如 n1 拿到 {1,3,5}），继续分岔；某节点找不到不相交冲突集就标 √，此时根到该叶子的边标号集合凑齐一个命中集。带圈号的 n0–n9 是标签复用的源头：它们的标签被抄给「路径与标签不相交」的后代节点，抄的节点不用再访问 F。读图结论：对这族冲突硬算，全部极小命中集是 6 个——{1,2}、{2,3,6}、{2,5,6}、{1,3,4}、{1,4,5}、{3,4,6}；抽验 {1,2}：逐一查 7 个冲突——{2,4,5} 有 2、{1,2,3} 有 1 和 2、{1,3,5} 有 1、{2,4,6} 有 2、{2,4} 有 2、{2,3,5} 有 2、{1,6} 有 1，全部命中，且去掉 1 或去掉 2 都会漏掉 {1,3,5} 或 {1,6}，确实极小。正文图3 的剪枝版把这 6 个 √ 叶子的代价压到 13 次访问 F。

3. **标签复用 + 三个剪枝手段（p.70–72）**：
    1. **标签复用**：已算出的节点标签 S，凡 $H(n') \cap S = \emptyset$ 的节点直接抄（树中以下划线标记），**零访问**；
    2. **关门（close）**：某 √ 节点的 $H(n) \subseteq H(n')$ 时，n' 不可能给出更小命中集，直接关门（×标记），**连 F 都不用访问**就能确定它不是极小命中集；
    3. **冗余边删除**：生成中发现某标签 S' ⊊ S（另一节点标签），则从 S 节点出发标以 $S - S'$ 元素的边及整个子树冗余，可删（")(" 标记）。
    - **这不行！→ 本文的绝招**：不能预先扫描 F 删掉超集（{2,4,5}、{2,4,6} 那样），因为 F 隐式定义、无法做先验子集测试——只能在树生长过程中"顺手"发现子集关系再回删（p.71–72）。
    - 例 4.7 剪枝后（图3, p.73）得到 6 个极小命中集，**13 次访问 F**。
4. **定理 4.8（p.72）**：剪枝 HS-tree 的 √ 节点 H(n) 集合 = F 的全部极小命中集。
    > 人话：树跑完之后，所有 √ 叶子上攒出的名单，不多不少正好是全部极小命中集（= 全部诊断）——剪枝没有剪丢任何解。
5. **算法 DIAGNOSE(SD, COMPONENTS, OBS)（p.76–77）**
    - **含义**：把"访问 F"换成调用函数 $TP$（**T**heorem **P**rover，定理证明器，下同）：节点需要标签时，标以
    $$\text{TP}(SD,\ \text{COMPONENTS} - H(n),\ OBS)$$
    它返回一个与 H(n) 不相交的冲突集（不存在则 √）。TP 只负责"要一个冲突集给一个"；**枚举顺序与终止判定的责任全部转移到树算法**。
    - **为什么需要**（p.75–76）：定理证明器可能以不同方式重复给出"本质相同"的变体反驳（Fig.5 给了两个归结反驳用同样 AB 实例的例子），且不能靠固定归结策略解决——那会绑死定理证明器。HS-tree 的复用+剪枝天然吸收这些冗余：**DIAGNOSE 对 TP 的任何两次调用绝不返回同一冲突集，且后一次绝不返回前一次的超集**（p.78）。
    - 代价核算（p.78）：图 6 的运行里 DIAGNOSE 只显式算了 12 个可能冲突集中的 **2 个**。
6. **TP 的实现自由度（p.78–79）**：完整反驳型定理证明器（记录 AB 实例）；直接从 SD∪OBS 推 AB 析取式（Genesereth DART 求 suspects 的方式）；专用求解器——Davis 与 de Kleer & Williams 的约束传播、开关电路的布尔方程求解器。建议缓存中间计算。若 TP 能保证只返回极小冲突集，冗余边剪枝永远不会触发，算法还能简化（p.79）。

## 六、单故障诊断（p.81–82）
1. **定义**：单元素诊断 = 单故障诊断；两个以上 = 多故障诊断。全加器：1 个单故障 {X1}，2 个多故障。
2. **为什么单故障特殊（p.81）**：部件通常独立失效 → 单故障诊断天然比伴生的多故障诊断更可信（全加器中 {X1} 优先于 {X2,A2}、{X2,O1}）。
3. **推论 4.10（p.81）**：{c} 是单故障诊断 ⟺ **c 出现在每一个（极小）冲突集中**。
4. **定理 4.11（p.81）**：只要**一个**冲突集 C 就能判定全部单故障诊断：{c} 是诊断 ⟺ c ∈ C 且 $SD \cup OBS \cup \{\neg AB(k) \mid k \in \text{COMPONENTS} - \{c\}\}$ 一致。
5. **定理 4.12（p.81–82）**：推广到若干个（不必全部）冲突集：取交集 C，c ∈ C 且上述一致性成立。
    > 人话：想确认「只有 c 坏」行不行，不必查全部冲突集——随便抓一个含 c 的冲突集，把除 c 以外的部件全假设成好的，能自洽则 c 就是一个（单故障）诊断。
    - **这不行！→ 为什么重要**：这正是 Davis 的"候选生成过程"（候选 candidate：此处指一个被怀疑的故障部件组合，即论文14 说的候选；constraint suspension，约束挂起：把候选部件的约束从模型里暂时摘掉，再看剩下部分自不自洽）。Reiter 用定理 4.12 给了这个未形式化过程一个**正式辩护**——"把 c 排除出 COMPONENTS"就是"关掉 c 的约束"（p.82）。

## 七、测量理论：测完之后诊断会发生什么（p.82–86）
1. **设定**：测量 $MEAS$（**MEAS**urement，一次测量新增的观测句子集，下同）= 附加观测（有限一阶句子集）；问 (SD,COMPONENTS,OBS) 与 (SD,COMPONENTS,OBS∪MEAS) 的诊断关系。典型场景：OBS 引出多诊断，MEAS 逐个甄别。
2. **定义 5.1：诊断"预测"H（p.82）**：诊断 Δ 预测句子 H（hypothesis，被预测的候选观测句，下同；与 §五命中集记号 H(n) 无关），若
$$SD \cup OBS \cup \{AB(c) \mid c \in \Delta\} \cup \{\neg AB(c) \mid c \in \text{COMPONENTS} - \Delta\} \models H$$（$\models$：逻辑蕴涵记号，左边一组公理逻辑推出右边句子，下同）
    **命题 5.3** 简化：等价于 $SD \cup OBS \cup \{\neg AB(c) \mid c \in \text{COMPONENTS}-\Delta\} \models H$。
    - 例 5.2（p.83）：例 4.9 电路中，{M1} 预测 out(M2)=6 且 out(M1)=4；{M2,M3} 预测 out(M2)=4 且 out(M3)=8。
3. **命题 5.4（p.83）**：不被任何诊断反驳的测量**不提供任何新信息**（诊断集不变）。
4. **命题 5.5（p.83）**：测量 H **保留**预测 H 的诊断；**否证**预测 ¬H 的诊断。
5. **这不行！** 直觉猜想："每个诊断都预测 H 或 ¬H 时，测 H 后剩下的恰好是原来预测 H 的那些。" **错误**——见下。
6. **定理 5.7（p.84）**：设每个诊断都预测 H 或 ¬H，则测量 H 之后：
    1. 预测 H 的旧诊断仍是诊断；
    2. 预测 ¬H 的旧诊断不再是诊断；
    3. **新出现的诊断必是某个预测 ¬H 的旧诊断的真超集**。
    > 人话：测一个新值，猜对的旧诊断留下，猜错的淘汰，还可能冒出更大的新诊断——测量既可能缩小也可能扩大候选名单，别默认它只会过滤。
> 数字拆解：为什么新诊断全变成三元素？实测 out(M2)=5 把中间变量 Y 直接钉死在 5。四个旧诊断逐一过堂：{M1}、{A1} 都默认 M2 正常 ⇒ Y 应为 6≠5，先毙；{M2,M3}、{M2,A2} 虽容忍 Y=5，但都假设 M1、A1 正常 ⇒ F=X+Y=6+5=11，与实测 10 矛盾，也毙。再看谁必须进每一个新诊断：M2 正常 ⇒ out(M2)=6≠5 ⇒ 「M2 坏」必在；M1、A1 全正常会推 F=12≠10 ⇒ 每个新诊断还需 {M1 或 A1} 之一；A2、M3 全正常会推 G=Y+Z=5+6=11≠12（Y 已钉 5）⇒ 还需 {M3 或 A2} 之一。三选一拼起来恰好 2×2=4 个三元素组合 [M1,M2,M3]、[M1,M2,A2]、[M2,M3,A1]、[M2,A1,A2]——这就是 Reiter 说的「以真超集再生」的具体形状。
    - 例 5.6（p.83–84）：测得 out(M2)=5。四个旧诊断 {M1}、{A1}、{M2,M3}、{M2,A2} 全都预测 out(M2)≠5（6 或 4），若猜想为真应全部消灭且无新生——实际上四个旧诊断被四个**真超集**新诊断取代：[M1,M2,M3]、[M1,M2,A2]、[M2,M3,A1]、[M2,A1,A2]。
    - **含义**：[[主动测量与诊断消歧]] 的第一个定律——诊断推理是**非单调**的，测量可以**扩大**候选空间而不只是过滤。一般情形下"分而治之"被堵死（p.85）。
7. **推论 5.8（p.85）**：系统真有故障时（∅ 不是诊断），新诊断必是多故障诊断。
8. **推论 5.9（p.85）**：**单故障诊断层面**可以放心分治——测量后幸存的单故障诊断恰好是原来预测 H 的那些。
    - 例 5.10（p.85）：{M1} 预测 out(M1)=4，{A1} 预测 out(M1)=6；测得 out(M1)=6 → {A1} 成为唯一可能的单故障诊断；实际剩余诊断 {A1}、{M2,M3}、{M2,A2}，且本例无新诊断产生。
9. **开放问题（p.86）**：何时测量只过滤不新增？新诊断能否从**已算好的剪枝 HS-tree** 直接导出（而不重算）？测试如何自动生成（Genesereth [8] 有一法）？——第一个和第三个问题分别被论文14（候选格增量更新）与论文15（从旧诊断增量计算）接棒。

## 八、推广：任意逻辑、默认逻辑与 GSC 模型（p.86–94）
1. **超越一阶逻辑（§6.1, p.86–87）**：检查全部定义与证明后发现只用到两个弱条件——(1) 语义二值；(2) 有 ∧,∨,¬ 及其通常解释。于是时变数字硬件 → 时序逻辑；时变生理数据 → 相应医学逻辑；数据库完整性约束违反 → 数据库逻辑。**多领域共享同一诊断理论是"鼓舞人心的统一观察"**（p.87）。
2. **诊断 = 默认逻辑（§6.2, 定理 6.1, p.87–89）**
    - **含义**：取默认理论 $DT$（**D**efault **T**heory，默认理论 = 一阶公理 + 默认规则，下同）：一阶公理 = SD∪OBS，默认规则为
    $$\frac{:\neg AB(c)}{\neg AB(c)} \quad (c \in \text{COMPONENTS})$$
    （即"若无矛盾则假设 c 正常"。记号读法：这条分数线上下各有一个 ¬AB(c)——横线上方的 ：¬AB(c) 是「一致性检查」，意思是当前信念库里还没有 c 坏的证据；横线下方的 ¬AB(c) 是「结论」，于是把「c 正常」写进信念库。每个部件一条这样的默认规则；一旦 SD∪OBS 的矛盾牵连到 c，这条默认被撤回、c 转入异常候选——这正是非单调「加信息反而删结论」的形式化。）则：**E 是 DT 的扩展 ⟺ 存在诊断 Δ 使 E = Th({H | Δ 预测 H})**。
    - 记号：$E$（extension，扩展——默认逻辑推理得到的一个信念集合，下同）；$Th(\cdot)$（theory，逻辑闭包，从给定句子集能推出的全部定理，下同）。
    > 人话：默认逻辑的一个「扩展」就是一种自圆其说的信念集合；该定理说，每种自圆其说恰好对应一个诊断——把哪些部件假设成坏，系统就恢复一致。
    - **为什么需要**：把"默认每个部件正常、观测矛盾时撤回最少的假设"精确落进 Reiter 自己的默认逻辑框架——**诊断天生就是非单调推理**，且诊断集合与扩展集合一一对应。顺带修掉了 [17] 里默认规则记号中误导性的 "M"（脚注 6, p.87）。
3. **与其他研究的关系（§7, p.89–91）**：
    - **de Kleer**：冲突集概念源头（1976，LOCAL：de Kleer 当年做的电路故障诊断程序，用电路模型推矛盾、报可疑元件）；LOCAL 是 SOPHIE（Xerox PARC 的电子电路计算机辅助教学系统——CAI，Computer Assisted Instruction，用程序当助教带学生做电路实验，学生接错线时由诊断部件报可疑元件）的诊断部件；
    - **Genesereth (DART)**：一阶逻辑表示 + 归结定理证明器求候选与测试；本文四点推广（任意逻辑、多故障形式化、全诊断算法、测量理论）；
    - **Davis**：约束传播、仅单故障、未形式化；定理 4.12 是对其候选生成过程的形式辩护；但其**桥接故障（bridge faults）**分析超出本理论——本理论要求**先验固定的部件清单**，结构本身坏掉没法表达（p.90）；
    - **Poole 等（Theorist）**：独立发现诊断-默认逻辑联系，但聚焦计算机制；
    - **Ginsberg（反事实）**：用反事实蕴涵定义诊断；Reiter 证明一阶情形下两者本质等价（与"protected formula"条件下诊断 ↔ 可能世界一一对应, p.91）。
4. **GSC 诊断模型的逻辑重构（§7.1, p.91–94）**
    - GSC（generalized set covering, Reggia, Nau & Wang）：诊断问题 = 四元组 (D, M, C, M⁺)——疾病集、表现集、因果关系、已观测表现；解释 = M⁺ 的**最小基数覆盖**（minimum cardinality cover：用**个数最少**的疾病把所有已观测异常都罩住——每个异常项至少由这组病里的一个引起。医生类比：化验单上五项异常，两种病能全解释掉就不选三种）。
    - Reiter 把它翻译进自己的框架（部件 = 疾病，SD 含公理 `OBSERVED(m) ⊃ PRESENT(d1) ∨ … ∨ PRESENT(dn)` 与"正常时疾病不出现"），然后证明（定理 7.1）：诊断 ⟺ M⁺ 的**极小覆盖**（minimal cover，按集合包含极小）。
    - **批评（p.93–94）**：最小基数覆盖 ⊊ 极小覆盖。GSC 会正确给出全加器的 {X1}，却**漏掉**直觉上合理的双故障 {X2,A2}、{X2,O1}。Reiter 认为"按基数取最小"不合适，应按包含取极小——并提到 Reggia 等人已独立采纳此观点。
    > 人话：Reggia 的模型主张"用个数最少的疾病解释症状"；Reiter 翻译后指出应取"不能再删的极小解释"。两者在全加器上分道扬镳：按个数最少只得到 {X1}，按极小还能保住 {X2,A2} 这类合理的双故障解释。

## 局限与启发（p.63–64, 79, 86, 90, 94）
1. **一般情形不可判定**："algorithm"的引号是认真的：一阶一致性无判定过程；实用前提是应用可判定（布尔方程/线性方程可行），不可判定就得回退启发式（p.64）。
2. **部件清单必须先验固定**：桥接故障、连接线断裂这类"结构差异"无法表示（p.90）——后来整个 fault-model / 结构变化诊断方向都在补这个洞。
3. **没有[[概率诊断]]、没有"下一步测哪里"**：第 5 节只回答"测量后诊断如何变"的定性问题，**没回答哪个测量最划算、也没法排序候选**——这正是论文14（最小熵 + 概率）与论文15（增量计算）的活。
4. **极小命中集个数仍可能指数**：HS-tree 省的是重复的定理证明，不省候选本身的组合爆炸。
5. **AI 运维映射**：这套"一致性 + 最小假设撤回"框架几乎原样映射到微服务根因分析——SD = 服务依赖与调用契约，COMPONENTS = 服务实例/组件，AB = 实例异常，OBS = 指标与日志断言；"多个竞争诊断"就是多假设根因；"测量"就是打点、探针、灰度实验；定理 5.7 提醒我们**新告警可能让根因假设集合变大**，别默认告警只会过滤假设。
