# 概念索引

> 全部概念解释页按区块分组；术语在论文笔记中首次出现处有浅显解释并链接到这里。

## A 协议基础与场景调研

- [[AMQP（高级消息队列协议）]]——OASIS+ISO 双标准的二进制消息协议，为企业消息中间件互操作而生，同时支持一问一答与发布订阅，路由灵活、支持事务。
- [[Broker（消息代理）]]——发布/订阅架构中居中的服务器：接收全部发布、按主题过滤并分发给所有订阅者。
- [[Cloudlet（微数据中心）]]——部署在移动设备附近（商场、校园等）的小型数据中心，作为移动设备与云之间的 edge 层。
- [[CoAP（受限应用协议）]]——面向受限设备（8 位 MCU、小内存）的 REST 风格 web 传输协议，跑在 UDP 上，最小二进制头 4 字节。
- [[Computing stream（计算流）]]——沿数据传播路径施加的一系列函数/计算；应用声明在哪里算，数据与状态随函数一起迁移。
- [[DDS（数据分发服务）]]——OMG 的数据中心、无 broker 的发布/订阅中间件标准，参与者通过「全局数据空间」直接交换数据。
- [[Exchange 与 Binding（交换器与绑定）]]——AMQP 的路由机制：exchange 按规则决定消息进哪个队列，binding 是连接 exchange 与 queue 的路由规则。
- [[HTTP（超文本传输协议）]]——网页世界通用的无状态一问一答（request-response）应用层协议，IoT 中用作 REST 服务的事实标准。
- [[IIoT（工业物联网）]]——IoT（物联网）在工业环境（工厂、电网、机床等）的应用子集，对可靠性与实时性的要求远高于普通 IoT。
- [[MQTT（消息队列遥测传输）]]——OASIS 标准的轻量发布/订阅消息协议，专为不可靠网络与间歇连接设计，跑在 TCP/IP 上。
- [[OPC UA（OPC Unified Architecture）]]——IEC 62541 标准系列的工业互操作通信架构，自带强大的数据与信息建模能力，Part 14 扩展出 broker-based 与 broker-less 两种发布订阅传输。
- [[PUBACK（发布确认）]]——MQTT QoS 1 中 broker 对 PUBLISH 的确认回执，保证 at-least-once（至少送达一次）。
- [[QoS 2 四次握手（4-way handshake）]]——MQTT QoS 2 的报文流程 PUBLISH→PUBREC→PUBREL→PUBCOMP，保证消息 exactly-once。
- [[QoS（服务质量）]]——消息协议中预先声明的送达承诺等级，约定「这条消息保证送到什么程度」。
- [[TCP（传输控制协议）]]——传输层的可靠传输协议：靠序列号、确认（ACK）、校验和、重传保证数据完整、有序、不重。
- [[UDP（用户数据报协议）]]——传输层的无连接传输协议：不保证送达、顺序、去重，但开销小、时延低、快。
- [[payload（消息载荷）]]——一条消息里真正要传送的数据内容（不含报文头等协议开销），大小以 bytes 计。
- [[丢包率]]——发出但未成功送达的消息/数据包占比。
- [[云卸载]]——把原本在云端对数据执行的操作（不只数据本身）下沉到边缘节点执行的模式。
- [[云计算]]——把计算与存储集中在远端大型数据中心、用户按需取用的计算模式。
- [[云边端协同]]——端设备、边缘节点、云三层算力如何分工、把任务分配到最合适一层的问题与机制。
- [[互操作性（interoperability）]]——两个以上系统交换信息并正确使用所交换信息的能力，分 technical（协议标准统一）、syntactical（数据格式统一）、semantic（数据含义统一）三层。
- [[单点故障（SPOF）]]——single point of failure：系统里一旦失效就会让整体停摆的单一部件。
- [[发布订阅模式]]——消息通信模式：发送者按主题发布、接收者按主题订阅，双方互不知道对方、经中间设施解耦。
- [[抓包（packet capture）]]——把网络上流过的每个数据包原样记录下来存成文件（pcap）供事后分析。
- [[抖动（jitter）]]——时延的波动程度：各次消息到达时间相对平均时延的忽大忽小。
- [[数据抽象]]——在边缘把杂乱、高频、不可靠的设备原始数据整理成上层服务可直接使用的统一表示。
- [[相关系数（correlation coefficient）]]——衡量两个变量是否同步变化的数值 r，范围 [-1,1]；越接近 1 同涨同跌越强。
- [[端到端时延]]——一条消息从发出方到接收方收下所经过的全部时间。
- [[组播（multicast）]]——multicast：一份数据经网络设备复制，同时发给一组已加入该组的接收者的分发方式。
- [[边缘计算]]——让计算发生在数据源与云之间路径上、靠近数据源一侧的使能技术集合（Shi et al. 2016 的定义）。
- [[遗嘱消息]]——MQTT 客户端连接时预先托付给 broker 的消息：设备异常掉线时由 broker 代为发布，向订阅者宣告该设备已失联。
- [[雾计算]]——在路由器、网关等网络基础设施层就近做计算的模式，与边缘计算基本同义、侧重不同。

## B 代理实现与性能评测

- [[C10M 问题（千万并发连接）]]——让一台服务器同时维持 1000 万条并发连接的经典工程挑战（C10M = 10 Million concurrent connections）。
- [[Kubernetes（K8s，容器编排系统）]]——自动管理大量容器的编排系统：负责容器在各机器上的部署、扩缩容、崩溃重启与网络入口。
- [[MST（最大可持续吞吐）]]——publisher 与 subscriber 都能长期稳定维持的最高消息速率（maximum sustainable throughput），超过它 broker 开始积压丢消息。
- [[RSS（接收侧扩展）]]——网卡的硬件分流技术（receive-side scaling）：按规则把进来的数据包拆给多个 CPU 核各自处理。
- [[SO_REUSEPORT（端口复用）]]——Linux 3.9+ 的 socket 选项：允许多个监听 socket 绑定同一个端口号，内核把新连接自动分摊给它们。
- [[StarlingX（开源边缘计算平台）]]——Linux 基金会旗下的开源边缘云/虚拟化平台，把普通服务器变成可容错的边缘节点来承载容器化应用。
- [[TLS（传输层安全协议）]]——给网络通信加密防窃听篡改的协议（Transport Layer Security），HTTPS 里的 S 就是它。
- [[epoll（IO 多路复用）]]——Linux 的高效事件通知机制：一个线程同时监视成千上万条 socket，只把「有数据到达」的活跃连接报告给应用。
- [[fanout 拓扑（广播扇出）]]——一个发布者广播、N 个订阅者各收一份消息的负载拓扑（相对地，1-to-1 是一发布者对一订阅者独占 topic）。
- [[native 实现与托管运行时（native vs managed runtime）]]——native = C/Rust/Go 等直接编译成机器码、自己管内存的实现；托管运行时 = Java/Erlang 等跑在虚拟机（JVM/Erlang VM）里的实现，由虚拟机代管内存与线程。
- [[事件循环（event loop）]]——一个「等事件 → 处理事件 → 再等事件」不停循环的线程，用少量线程处理大量连接。
- [[内核旁路（kernel bypass）]]——让网络数据包绕过操作系统内核的 TCP/IP 栈、由应用程序在用户态直接处理的技术路线；mTCP 是用户态 TCP 栈，DPDK 是它运行所需的高速包 I/O 底座。
- [[吞吐（throughput）]]——系统每秒成功处理/送达的消息条数（msg/s），衡量「干得多快」。
- [[基准测试（benchmark）]]——用固定、可复现的负载去考核一套系统并量化其成绩的标准化测试方法。
- [[对称场景（symmetric workload）]]——发布方与订阅方数量均衡的基准测试场景（论文6 用 10 publisher + 10 subscriber），与扇入/扇出相对。
- [[尾时延与分位数（p50 与 p95）]]——把所有请求耗时从小到大排队，p50 = 排中间的值（一半请求比它快），p95 = 95% 位置的值（只有 5% 比它慢）；尾时延（tail latency）指最慢那一小撮请求的耗时。
- [[崩溃注入测试]]——系统稳定运行时故意杀掉某个组件，观察系统能否自动恢复、恢复期间丢不丢数据的韧性测试方法。
- [[开环负载与令牌桶（open-loop 与 token bucket）]]——开环（open-loop）：测试工具按自己设定的节奏发负载、不等 broker 的确认或反压信号；令牌桶（token bucket）：按固定速率往桶里攒「令牌」、每发一条消息消耗一枚，实现精确限速。
- [[故障注入与 MTTF、MTTR（fault injection）]]——故障注入：故意在系统里制造故障来考验容错能力；MTTF/MTTR：平均无故障时间 / 平均恢复时间，一对控制「故障节奏」的参数。
- [[读写锁（read-write lock）]]——一把锁的两种持有方式：读锁可多人同时持有（并发「看」），写锁一人独占（「改」时谁都不能进）。
- [[负载均衡器]]——把客户端连接轮流分发给后台多个服务器实例的中间层，对外只暴露一个统一地址。

## C 分布式组网与边云桥接

- [[IBR 与 SPR（流量权衡两参数）]]——IBR = 对某 topic 感兴趣的 broker 占比；SPR = 订阅总字节/发布总字节之比。两者决定 SF vs PF 谁省流量（式 5，拓扑无关）。
- [[MQTT 桥接（MQTT Bridge）]]——在两个 broker 之间转发消息的机制/组件：源 broker 某 topic 上的数据，在目的 broker 的对应 topic 上对订阅者可用。
- [[No Local 与 Retain As Published]]——MQTT 5.0 为桥接场景提供的两个订阅选项：No Local 不把消息回发给发布者自己；Retain As Published 保留原消息的 retained 标志。
- [[Publication Flooding（PF，发布泛洪）]]——broker 间分发机制之一：每条发布消息复制给所有 broker，订阅只在本地处理。
- [[Selective Subscription Forwarding（SSF，选择性订阅转发）]]——论文8 提出的机制：转发订阅前先做 topic 包含判定，只转发未被已有订阅包含的订阅，使 broker 间订阅永不重复、永不重叠。
- [[Subscription Flooding（SF，订阅泛洪）]]——broker 间分发机制之一：泛洪每条订阅，发布消息沿精确路径只发给需要的邻居。
- [[Topic 包含关系（topic containment）]]——记作 x ⊑ y：topic x 的任何可能语义都落在 y 里（y 覆盖 x）；判定它的 MSCP 问题在 MQTT 语法约束下可线性时间求解。
- [[Topic（主题）]]——MQTT 消息的「频道名」：用斜杠 / 分层的字符串，broker 按它把消息分发给订阅者。
- [[传输成本大于处理成本]]——论文9 的核心推断：跨网络搬运数据一个来回的代价（时间、丢失风险）大于在本地 CPU 上做转换处理的代价。
- [[分布式 broker 网络（distributed broker network）]]——多个 broker 各管一片设备、彼此连成网络协同分发的架构；消息必须能跨 broker 送达所有感兴趣的客户端。
- [[服务时延（service latency）]]——从 publisher 发出消息到 subscriber 收到消息的时间跨度——发布/订阅系统端到端时延的标准口径。
- [[跨组织情境（Cross-Organizational Context）]]——数据的生产方与消费方分属不同机构/公司，互相无管理权限、不默认信任对方。
- [[通配符订阅（Wildcard Subscription）]]——订阅时用 # 或 + 等通配符一次匹配一批 topic 的订阅方式。
- [[通配符（wildcard）]]——订阅 topic 时可用的「万能牌」：+ 代表任意一层，# 代表其后所有层。

## D 可靠性容错与安全

- [[AOTP（进阶一次性口令）]]——论文12 实现并实测的 topic 混淆方案：OTP + hash 链 + 每步掺盐（随机多项式）。
- [[CPU 配额（CPU quota）]]——给进程限制可用算力的手段（限频、cgroup、cpulimit 等统称）。
- [[Diffie-Hellman 密钥交换（DHKE）]]——两方在公开信道上公开交换信息、最终各自算出同一个共享密钥的协议。
- [[Nagle 算法（Nagle's algorithm）]]——TCP 的「攒单发货」优化：把小数据包攒一攒再发。
- [[RTT（往返时延）]]——一条消息从发出到收到确认的来回耗时。
- [[Time Factor（时间系数）]]——论文11 自定义指标：实际发完全部消息的耗时 ÷ 理论最小耗时，TF=1 即最优。
- [[hash 链（Hash Chain）]]——把同一个 hash 函数反复套用得到的一串值：上一环的输出是下一环的输入。
- [[一次性口令（OTP）]]——每个口令只用一次、用完作废的认证/命名思路（如动态验证码）。
- [[伪随机函数（PRF）]]——给定种子即产出一串看似随机、但同种子各方算出相同结果的函数。
- [[保留消息（Retained Message）]]——broker 为每个 topic 保存的'最后一条留言'：新订阅者一订阅就立刻收到，不用等下一次发布。
- [[元数据（Metadata）]]——「关于数据的数据」：通信内容之外的外围信息（谁、何时、用什么标签、发了多大）。
- [[区块链命名服务（Blockchain Naming Service, BNS）]]——把'域名 → 当前 broker'的地址簿放在区块链合约上：客户端永远连一个固定域名，背后指向可迁移。
- [[区块链账本（Blockchain Ledger）]]——区块链的存储核心：一串带哈希指针的块，数据一旦写入几乎不可篡改，全网各节点各存一份。
- [[持久会话（Persistent Session）]]——客户端要求 broker 记住自己的订阅与未送达消息（clean session=false / MQTT 5 的 session expiry），断线重连后接着收。
- [[智能合约（Smart Contract）]]——部署在区块链上的程序：满足条件自动执行，其状态与执行记录由链保障不可篡改。
- [[死信队列与死信交换（DLQ、DLX）]]——存'没被签收的消息'的队列：QoS>0 的消息未被确认时不丢弃，先归档，等接收方回来再补发。
- [[端到端加密（End-to-End Encryption）]]——只有收发两端能解密、中间节点只见密文的加密方式。
