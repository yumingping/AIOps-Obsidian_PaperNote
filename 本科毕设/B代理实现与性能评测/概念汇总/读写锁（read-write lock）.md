# 读写锁（read-write lock）

**一句话定义**：一把锁的两种持有方式：读锁可多人同时持有（并发「看」），写锁一人独占（「改」时谁都不能进）。

**通俗解释（研0 版）**：像共享文档：大家同时看没问题；有人正在编辑时锁定，别人既不能改也不能看（防止读到改一半的状态）。适合读多写少的场景——muMQ 的 topic 树 PUBLISH 加读锁并行匹配、SUBSCRIBE 加写锁改树。

**关键要点**
- 读多写少才划算，写多时退化成普通互斥锁
- 锁粒度影响并发度：muMQ 锁整棵树的根节点，简单但全局互斥
- 锁竞争是吞吐损耗来源：论文5 中 subscribe rate > publish rate 的根因
