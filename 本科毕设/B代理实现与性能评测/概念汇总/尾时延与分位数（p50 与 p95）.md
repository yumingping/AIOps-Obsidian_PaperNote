# 尾时延与分位数（p50 与 p95）

**一句话定义**：把所有请求耗时从小到大排队，p50 = 排中间的值（一半请求比它快），p95 = 95% 位置的值（只有 5% 比它慢）；尾时延（tail latency）指最慢那一小撮请求的耗时。

**通俗解释（研0 版）**：均值像「平均工资」——会被少数极端值拉高，看不出大多数人；分位数像「中位数 + 前 95% 的水平线」，能同时告诉你「典型体验」和「最坏体验」。用户感到的「偶尔卡一下」就来自尾时延。

**关键要点**
- p50 看典型、p95/p99 看最坏，必须同时报
- JVM 系的 P95 与 P50 差距大（GC 停顿导致方差大）
- 故障恢复窗口会把所有人的 P99 拉到秒级——与 broker 实现无关，归因时要分层
