# 吞吐（throughput）

**一句话定义**：系统每秒成功处理/送达的消息条数（msg/s），衡量「干得多快」。

**通俗解释（研0 版）**：像高速路口每秒放行的车流量。注意口径：谁统计（broker 收到的 vs 发给订阅者的）、统计窗口（只算稳定期还是含连接建立阶段）都会改变数字——论文5 分 subscribe rate / publish rate 两个口径，两者差值还能诊断锁竞争。

**关键要点**
- 饱和点：再加负载吞吐也不再上涨的拐点，是压测要找的关键值
- subscribe rate 与 publish rate 分开报（论文5 口径）
- 吞吐只统计稳定期、排除连接建立阶段（论文7 口径）
- 必须与 CPU/内存占用同采才有意义，否则无法回答「边缘能不能跑」
