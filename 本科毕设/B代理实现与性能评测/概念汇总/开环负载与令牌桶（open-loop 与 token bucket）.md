# 开环负载与令牌桶（open-loop 与 token bucket）

**一句话定义**：开环（open-loop）：测试工具按自己设定的节奏发负载、不等 broker 的确认或反压信号；令牌桶（token bucket）：按固定速率往桶里攒「令牌」、每发一条消息消耗一枚，实现精确限速。

**通俗解释（研0 版）**：开环像「按固定时间表发货的工厂」——无论仓库（broker）多挤，照常发货，这样才暴露仓库真实的饱和点；闭环则像「仓库喊停就暂停发货」，会把 broker 的过载问题藏起来。令牌桶是实现「每秒恰好 N 条」最常用的算法。

**关键要点**
- 闭环压测会把 broker 的饱和行为测不准
- 吞吐只统计稳定期（排除连接建立阶段）
- fanout 实验需提高发送速率（论文7 用 100 msg/s）才能压出饱和
