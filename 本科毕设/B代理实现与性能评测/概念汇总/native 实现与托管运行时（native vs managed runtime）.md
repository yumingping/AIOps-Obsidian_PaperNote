# native 实现与托管运行时（native vs managed runtime）

**一句话定义**：native = C/Rust/Go 等直接编译成机器码、自己管内存的实现；托管运行时 = Java/Erlang 等跑在虚拟机（JVM/Erlang VM）里的实现，由虚拟机代管内存与线程。

**通俗解释（研0 版）**：native 像「自己开车」：事事自己安排，快且省资源，但要自己操心；托管运行时像「打车」：司机（虚拟机）代管一切，省心、生态全，但要付「车费」（GC 停顿、内存开销）。论文7 数据：JVM 系内存高 10–50 倍、大 payload 慢 2–3 倍；但资源给足（4 vCPU）时 Artemis 能反超。

**关键要点**
- GC（垃圾回收）停顿是托管运行时尾时延的元凶
- 受限边缘硬件（1–2 vCPU）上托管运行时易 OOM/崩溃
- 资源给足后托管运行时能反超（Artemis 70K msg/s）——选型按资源约束定
- 毕设自研 broker 建议走 native 路线（Rust/Go/C）
