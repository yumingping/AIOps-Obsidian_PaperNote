# MQTT 桥接（MQTT Bridge）

**一句话定义**：在两个 broker 之间转发消息的机制/组件：源 broker 某 topic 上的数据，在目的 broker 的对应 topic 上对订阅者可用。

**通俗解释（研0 版）**：桥就是两个'快递中转站'之间的定班车：源站把某些频道的件装上桥，目的站卸货上架。关键分野是桥装在哪一侧：broker 侧桥接（如 Mosquitto bridge）是中转站自带的内部通道，要求两边同构、无管理壁垒；client 侧桥接是挂在 broker'客户端'位置的独立组件，可以顺手做格式转换——跨组织时对方系统你管不着，只能在自己出口放 client 侧桥。

**关键要点**
- bridge 把一个环境的生产数据流与另一个环境解耦（论文9 p.3）
- broker 侧桥接（Mosquitto bridge）：实现简单，但要求同构、无转换、无管理壁垒——跨组织不可行（论文9 p.1）
- client 侧桥接：bridge 作为 broker 的客户端订阅→转换→再发布，可合并异构格式、统一数据模型，转换后体积反而变小（论文9 p.4）
- 跨组织桥接三类动因：异构传感器数据处理、受限链路优化、地理分离（论文9 p.3）
- 桥接粒度两种：按 provider 聚合（少实例少链路）vs 按流拆分（多实例多链路），论文9 实测前者延迟更低
