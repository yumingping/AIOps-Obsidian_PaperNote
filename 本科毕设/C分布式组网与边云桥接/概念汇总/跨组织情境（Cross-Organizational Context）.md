# 跨组织情境（Cross-Organizational Context）

**一句话定义**：数据的生产方与消费方分属不同机构/公司，互相无管理权限、不默认信任对方。

**通俗解释（研0 版）**：同一组织内传数据像公司内部走内部流程，想怎么改系统都行；跨组织像两家公司之间做生意——要过防火墙、签接口约定，对方用你不认识的格式也得做转换。论文9 的核心设定：传感器数据是 A 组织的，数据平台是 B 组织的，中间隔着管理壁垒（administrative barrier：你管不到我的服务器）和信任边界（trust boundary：跨界数据默认不可信，要加密、鉴权）。

**关键要点**
- 管理壁垒：一方无权改造另一方的 broker，直接排除了 broker 侧桥接（论文9 p.1）
- 信任边界：跨界链路要 TLS 加密、LDAP 认证授权，这些开销都计入实测延迟（论文9 p.7）
- 异构：各 provider 用不同 MQTT 方案与数据格式，必须在边界处转换（论文9 p.1）
- 论文9 用 OWASP threat modeling 记号在架构图上标注组织边界
