**最重要 10 条事实**（页码均为 PDF 物理页码，置信等级：确定，引自规范原文）：
1. 报文首字节高 4 位为类型值 1–15，低 4 位 flags：仅 PUBLISH 用 DUP/QoS/RETAIN；PUBREL/SUBSCRIBE/UNSUBSCRIBE 固定 `0010`，其余全 0（Table 2-1/2-2，p.21–23）。
2. Remaining Length 是变长字节整数（VBI），只算变长头+Payload，不含自身；VBI 每字节低 7 位+续位，最多 4 字节，上限 268,435,455，必须最少字节编码（§1.5.5，p.18–19）。
3. 30 个属性 ID 全表在 p.25–26（如 Session Expiry 0x11、Receive Maximum 0x21、Topic Alias 0x23、User Property 0x26）；无属性也必须写 Property Length=0。
4. CONNECT 变长头顺序固定：Protocol Name "MQTT" → Level=5 → Connect Flags → Keep Alive → Properties；Connect Flags bit0 必须为 0（p.30–32）。
5. Keep Alive：非零时 Client 必须发 PINGREQ；Server 1.5× 超时必须断开（[MQTT-3.1.2-22]，p.34）。
6. QoS2 四步握手：PUBLISH→PUBREC→PUBREL→PUBCOMP；发出 PUBREL 后禁止再重发 PUBLISH（§4.3.3，p.95–97）。
7. **v5 重发规则收紧**：只有 Clean Start=0 重连且 Session 存在时才必须重发未确认 PUBLISH/PUBREL（原 PID），其他时刻一律禁止（[MQTT-4.4.0-1]，p.96）。
8. 主题语法：`#` 必须独立或紧跟 `/` 且居末；`+` 必须独占一层；`#`/`+` 开头的 Filter 不匹配 `$` 主题（p.98–100）。
9. 订阅选项字节：QoS(0-1)、No Local(2)、Retain As Published(3)、Retain Handling(4-5，值 3 非法)；流控 Receive Maximum 通过 send quota 扣减/补回（p.73、103–104）。
10. 增强 AUTH 是 OPTIONAL；Server 也可发 DISCONNECT；TLS 建议端口 8883（§4.12、3.14、5.1）。另外发现规范内部两处自相矛盾（Retain Handling=1 的附录 B 表述、CONNECT Payload 顺序漏 Will Properties），已记入 digest「冲突」节。
