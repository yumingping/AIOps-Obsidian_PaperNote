**最重要 10 条事实**（详见 digest，含条目编号）：
1. 报文类型 1–14 固定：CONNECT 1/CONNACK 2/PUBLISH 3/PUBACK 4/PUBREC 5/PUBREL 6/PUBCOMP 7/SUBSCRIBE 8/SUBACK 9/UNSUBSCRIBE 10/UNSUBACK 11/PINGREQ 12/PINGRESP 13/DISCONNECT 14；0 与 15 禁用（p.16–17）。
2. required flags：PUBREL/SUBSCRIBE/UNSUBSCRIBE 固定 0010，其余（除 PUBLISH 的 DUP/QoS/RETAIN）全 0；非法 flags 必须关连接（p.17–18）。
3. Remaining Length 变长编码：低 7 位数据 + 最高位继续位，最多 4 字节，上限 268,435,455（256 MB，0xFF 0xFF 0xFF 0x7F）（p.18–19）。
4. UTF-8 串 2 字节长度前缀、上限 65535 字节；ill-formed UTF-8 或 U+0000 → MUST 关连接（p.13–14）。
5. CONNECT：Protocol Name "MQTT"、Protocol Level **4**、Payload 顺序 ClientId→Will Topic→Will Message→User Name→Password；ClientId MUST 接受 1–23 字节 `[0-9a-zA-Z]`，0 字节 ID 必须 CleanSession=1 否则回 0x02（p.23–30）。
6. CONNACK 返回码仅 0x00–0x05（接受/协议版本/identifier/不可用/坏凭证/未授权）；非零码后必须关连接；bit0 是 Session Present（p.31–33）。
7. Keep Alive：Client 端保间隔、无报文时发 PINGREQ；Server 端 **1.5×Keep Alive** 未收报文必须断开；0 关闭心跳（p.27–28）。
8. SUBACK 返回码仅 0x00/0x01/0x02/**0x80（失败）**；实际投递 QoS = min(发布 QoS， 授予 QoS)（p.43–44）。
9. QoS2 四步握手：PUBLISH→PUBREC→PUBREL→PUBCOMP；去重前提是 Receiver 在 PUBREL 到达前对同 packet id 一律重回 PUBREC 且不重复投递，Sender 发出 PUBREL 后不得再发 PUBLISH；packet id 到 PUBCOMP 才可复用（p.54–55）。
10. 重发只在 CleanSession=0 重连后按原 packet id 重发未确认的 QoS1/2 PUBLISH 与 PUBREL——这是规范唯一强制重发场景（p.55）；topic 匹配逐字符、无归一化，`#` 必须末尾独立成层、`+` 独占一层、`$` 开头不被通配 filter 匹配（p.57–59）。

**与 5.0 最重要的 3 个差异**：① 无 Properties 属性区；② PUBACK/DISCONNECT 等无数值化 reason code（错误路径 = 直接关连接）；③ 无 shared subscription、message expiry、topic alias，session 寿命只有 CleanSession 二选一、不可协商（p.16–50 全文无对应字段）。

**三档一句话**：🔴 编解码 + CONNECT/CONNACK + QoS0/1 + 订阅/心跳/topic 匹配/retained/持久会话是互通底线；🟡 QoS2 四步握手、Will、认证、重发保序、WebSocket 可中期补；🟢 第 5 章安全指导、附录审计、256 MB 上限、合规与 Unordered Topic 直接跳过。
