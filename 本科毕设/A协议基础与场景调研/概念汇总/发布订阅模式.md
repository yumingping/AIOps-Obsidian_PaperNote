# 发布订阅模式

**一句话定义**：消息通信模式：发送者按主题发布、接收者按主题订阅，双方互不知道对方、经中间设施解耦。

**通俗解释（研0 版）**：报社与订户：报社只管按栏目出版，订户只管订自己要的栏目，互相不认识。好处是收发双方完全解耦，加人撤人都不影响对方；代价是需要中间分发设施，且发送方不知道消息有没有被收到。

**关键要点**
- MQTT/AMQP/DDS/XMPP 是四种发布订阅变体（论文2 p.9–14）
- 空间解耦（不在同一台机器也能通信）；DDS 连时间都解耦（发收双方不必同时在线，论文2 p.13）
- 与 request-response（一问一答）相对，HTTP 是后者的代表（论文2 p.8, 11）
- 毕设的 MQTT 模块就是该模式的实现；订阅扇出是主要性能变量（trans_msg = n × topic_average，论文2 p.20）
