# 区块链命名服务（Blockchain Naming Service, BNS）

**一句话定义**：把'域名 → 当前 broker'的地址簿放在区块链合约上：客户端永远连一个固定域名，背后指向可迁移。

**通俗解释（研0 版）**：传统 DNS 像 114 查号台：问'XX 餐厅电话'，它报个号码，号码错了你就找不到店。BNS 是一本改账要经过合约、全网见证的电话总机：客户端永远只拨一个号码（BNS 域名），总机背后把线接到哪台 broker 由合约与负载均衡器实时决定——broker 坏了就接到另一台，客户端无感。

**关键要点**
- 客户端连接地址与实际 broker 解耦：broker 失效/过载时做 topic 迁移，客户端不丢数据（论文10 p.4）
- 本质功能 = DNS + 健康检查 + 指针迁移；中心化部署用传统负载均衡即可等价实现且时延更低（笔记检视层判断）
- 是论文10 唯一真正'新增'于 MQTT 规范的能力：规范没有任何 broker 侧故障切换机制（p.2–3）
