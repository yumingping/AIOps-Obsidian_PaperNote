# 死信队列与死信交换（DLQ、DLX）

**一句话定义**：存'没被签收的消息'的队列：QoS>0 的消息未被确认时不丢弃，先归档，等接收方回来再补发。

**通俗解释（研0 版）**：快递点里'无人认领包裹架'：你不在家（订阅者离线/断连），包裹不能扔，先放上架子（死信队列），等你回来凭同一取件码（相同 session ID 重连）一次性取走。MQTT 规范里这个架子放在 broker 内存里，架子大小受硬件限制；论文10 把整个架子搬上区块链（DLX 合约），broker 内存压力解除——但每件包裹上架都成了链上交易，代价未量化。

**关键要点**
- MQTT 语境：QoS 1/2 未确认消息由 broker 维护，受系统内存限制（论文10 p.1）
- 论文10 的 DLX 合约：消息入链上队列、订阅者不确认就不弹出、unclean session 重连时整批取回补发（p.3–4）
- 与 MQTT 自带 persistent session 功能重叠：规范本就允许 broker 为持久会话缓存未确认消息，论文未对比（笔记检视层判断）
- 毕设落法：DLX 思想 = 本地落盘补发（SQLite/文件），不需要区块链
