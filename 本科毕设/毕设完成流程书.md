## 〇、怎么用这本流程书

- **每周五自查**：对照当周「产出」勾项，没完成的决定是周末补还是顺延到缓冲周，不许无意识地滑走。
- **每周日写周记**：模板见附录 6.1；周记写的是「做了什么 + 卡在哪 + 下周做什么」，正好是当周计划的反照。
- **符号约定**：🟥 教务硬节点（不可动）；🟨 本流程书自设的提前节点；⬜ 空载/轻任务周（节假日）。
- 每周条目固定四块：**目标 / 动作 / 去找什么 / 产出（+组会与周记）**。
- 论文引用一律走 `[[…]]` 双链到已有笔记；本流程书**不新增论文、不新建概念页**，缺概念直接用粗体术语（遵守 CLAUDE.md）。

## 三、环境与资源清单

### 3.1 Ubuntu 22.04 开发环境（W2 一次性装齐）

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git gdb \
  libsqlite3-dev libssl-dev libasio-dev \
  mosquitto mosquitto-clients \
  wireshark tshark tcpdump
# Docker（官方脚本或 apt install docker.io），拉取：
#   emqx/emqtt-bench（压测）、emqx/nanomq、emqx（EMQX 5）
```

- 工作计划里写「GCC 17」，实际含义是 **GCC + C++17 标准**：Ubuntu 22.04 自带 GCC 11 完全够用，不必折腾升级工具链。
- CLion 建 CMake + Ninja 工程；VSCode 用来改 vault 笔记和看日志；两者共享同一仓库即可。
- Wireshark 过滤 MQTT：`tcp.port == 1883`，解析器直接认 MQTT 报文，QoS 状态机验证靠它。

### 6.2 性能测试指标口径（与 [[7IoT边缘消息代理基准测试]] 对齐）

| 指标 | 定义 | 工具/来源 |
|---|---|---|
| 连接数 | 并发 TCP + MQTT 会话数（每连接 1 订阅） | emqtt-bench `conn` 模式 |
| 吞吐 | msg/s，pub:sub 固定，fanout ∈ {1, 10, 100} | emqtt-bench `pub/sub` 模式 |
| 时延 | pub 端打点 → sub 端收到的端到端，报 p50/p95/p99 | 消息内嵌时间戳脚本 |
| 可靠性 | QoS1/2 消息完成率、重连时延、重发条数 | paho 脚本 + tc netem 注入 |
| 资源 | 进程 RSS、CPU%（容器配额固定 1 vCPU / 512 MB 起步） | docker stats 采样脚本 |
| 边缘侧 | 树莓派上同口径缩小规模（连接数 ≤1k） | 同一套脚本 |
